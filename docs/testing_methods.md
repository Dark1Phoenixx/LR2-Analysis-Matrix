# Сравнение методов тестирования

| Метод | Преимущество | Ограничение | Применение в проекте |
| --- | --- | --- | --- |
| Эквивалентное разбиение | Сокращает набор входов до типовых классов | Редкие комбинации могут остаться непроверенными | JSON-объект, массив, пустой payload |
| Граничные значения | Находит ошибки знака и сравнения | Требует осмысленных границ | −1, 0, 1, 2 для размерностей, sin(0) |
| Покрытие операторов | Показывает невыполненный код | Не гарантирует оба исхода решений | Обзор исходников через Coverage.py |
| Покрытие решений | Требует каждый исход решения | Может пропустить часть условий внутри выражения | Успех и ошибка для версии и входного JSON |
| Покрытие условий | Проверяет оба значения каждого предиката | Не перебирает сочетания значений | Тип версии, признак bool, равенство 1 |
| Комбинаторное покрытие | Проверяет совместное влияние предикатов | Число наборов растёт, часть наборов недостижима | Шесть наборов для трёх предикатов версии |

Для проверки JSON-контракта выбраны сочетания предикатов и граничные
размерности. Для проверки пользовательского поведения применяются файловые
сценарии и регрессия. Метрика ветвей Coverage.py оценивает переходы между
строками кода, поэтому матрица предикатов ведётся отдельно.
