# Результаты интеграционного тестирования

Тестирование начинается с прямого вызова нижнего вычислительного модуля, затем проверяет контракты входа, worker и файловый JSON-обмен. Набор включает успешные сценарии, граничный размер 1×1, нулевые/отрицательные и неверно типизированные размерности, неправильную версию протокола, недоступность worker, таймаут и отсутствие файла ответа. Текущий набор содержит 14 тестов.

## Сценарии

| № | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| 1 | Прямой вызов для матрицы 2×3 | `positive_count = 5` |
| 2 | Размер 1×1 | `positive_count = 0` |
| 3 | Нулевая или отрицательная размерность | Отказ до запуска worker |
| 4 | `bool`, число с дробной частью вместо размерности | Ошибка типа входных данных |
| 5 | Несовместимая версия | Диагностируемая ошибка версии протокола |
| 6 | Полный JSON-обмен через worker | Ответ сохранён, статус `ok` |
| 7 | Таймаут или отсутствие worker | `IntegrationError` с причиной |
| 8 | Worker не создал ответ | Ошибка файлового контракта |

Команда запуска: `python -m unittest discover -s tests -v`.

Результат проверки версии v1.1.0: 14 тестов выполнены успешно. Для размерности 2×3 получено 5 положительных элементов, для 1×1 — 0. В GitHub Actions запуск Integration №2 завершился успешно.
