# Сравнение стратегий интеграции

| Стратегия | Преимущество | Ограничение | Когда выбирать |
| --- | --- | --- | --- |
| Нисходящая | Рано проверяется общий сценарий | Для нижних модулей нужны заглушки | Управление и интерфейс определяют работу системы |
| Восходящая | Сначала проверяются вычислительные компоненты | Полный сценарий появляется после сборки верхнего уровня | Есть самостоятельные алгоритмы и понятные интерфейсы |
| Сэндвич | Верхние и нижние компоненты проверяются параллельно | Требуется согласовать драйверы и заглушки | Система разделена на несколько слоёв |
| Риск-ориентированная | Рано обнаруживаются ошибки сложных компонентов | Требуется оценить риски до начала работы | Есть нестабильный интерфейс или сложный алгоритм |
| Функционально-ориентированная | Сначала получается законченная функция | Общие модули могут потребовать доработки | Возможна поэтапная поставка функций |
| Т-образная | Рано проверяется путь через все слои | Первый сквозной сценарий охватывает лишь часть функций | Нужно проверить архитектуру многослойной системы |

Для анализа матрицы применяется восходящая стратегия варианта 20. Сначала тестовый драйвер проверяет подсчёт положительных элементов. Затем подключаются worker, JSON-файлы, проверка входных данных и вывод результата.

Функция обработки принимает две размерности и возвращает целое число. Такой интерфейс позволяет проверить алгоритм до файлового обмена и запуска отдельного процесса.
